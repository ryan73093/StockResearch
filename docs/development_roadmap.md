# 盤後決策台 — 開發路線圖

更新：2026-09-30。本檔是階段、工作包、狀態與工時的唯一來源。需求寫在 [`REQUIREMENTS.md`](../REQUIREMENTS.md)，架構寫在 [系統架構](system_architecture.md)，每輪交付與證據寫在 [`DEVELOPMENT_HISTORY.md`](../DEVELOPMENT_HISTORY.md)，當前工作包寫在 [交接記錄](development_handoff.md)。

狀態代碼：`done` 完成（有程式、測試、實際執行證據）、`doing` 進行中、`todo` 待開始、`blocked` 等待外部條件。工時為 AI 協作初估工作天，每個階段完成後依實際進度重估。

## 總覽

合計初估 42–61 工作天。S5 可在 S4 進行時先用定期定額與再平衡等基準策略開發；S4 產生的冠軍策略晉級後才接入每日建議。

里程碑：
- M1（S1 + S2 完成）：每日流程穩定、資料庫瘦身、可從 Cloudflare 用手機開啟新介面骨架與專案資訊頁。
- M2（S3 + S5 基準版完成）：「今日」頁每天給出定期定額／再平衡的委託單，並與定期定額影子帳戶對帳。
- M3（S4 第一批研究完成）：產出第一份研究報告；有通過門檻的策略則開始前向模擬。
- M4（前向模擬 8–12 週後）：決定是否把研究策略接入每日建議。

## S2 Cloudflare 發布與新介面骨架

目標：用手機透過 Cloudflare 安全開啟網站；新介面骨架上線，之後每輪交付都在本機與 Cloudflare 兩端驗收。

| 工作包 | 內容 | 驗收 |
|---|---|---|
| S2-W01 Access 驗證 | 移植 VectorDB `access_control.py` 模式：驗證 `Cf-Access-Jwt-Assertion`（RS256、audience、issuer、email）、單一擁有者 email 允許清單、本機 loopback 開發模式、跨來源寫入拒絕、安全標頭；新增 `PyJWT`、`waitress` 依賴 | 無 JWT、錯誤 audience、非允許 email 都被拒絕；本機 loopback 可用；測試涵蓋 |
| S2-W02 專屬 Tunnel | 建立 Tunnel `stockresearch-pimi-sunsun`（憑證放 `.runtime/cloudflared/`）、DNS `stockresearch.pimi-sunsun.com`、Access self-hosted application（Google 登入 + 擁有者 email）；啟動器核對 origin `/health` 後才啟動 Tunnel，並記錄 PID | 手機開啟 `https://stockresearch.pimi-sunsun.com` 需 Google 登入；未授權帳號被擋；Tunnel 連線數 ≥ 1 |
| S2-W03 新版面骨架 | 設計 token（淺色、手機優先）、共用頁面骨架、底部／側邊導覽只有 今日／持倉／計畫／研究／系統；首頁 `/` 改為輕量「今日」頁；舊頁面（含舊市場總覽）移到「研究 › 舊版工具」 | 375 px 寬無水平捲動；導覽 5 項；首頁熱快取 < 2 秒；舊功能仍可進入 |
| S2-W04 專案資訊頁 | 系統頁內的「專案資訊」：路線圖、架構（Mermaid 渲染）、需求、交接、開發歷程，直接讀取 docs 原始檔 | 兩端都能看到與 repo 一致的文件內容 |
| S2-W05 開機自動恢復 | 開機排程啟動 App、Worker、Tunnel；每日 SQLite 線上備份 | 重開機後兩端自動恢復；備份檔可還原 |

依賴：S1-W04。子網域已定案 `stockresearch.pimi-sunsun.com`（2026-09-30）。需要使用者：在 Cloudflare Zero Trust 建立 Access application，或提供操作授權。

## S4 AI 研究迴圈（策略工廠）

目標：AI 研究員自動提出、測試、淘汰策略；只有通過統計門檻與前向模擬的規則才能晉級。

| 工作包 | 內容 | 驗收 |
|---|---|---|
| S4-W01 試驗登錄 | 每次試驗保存 spec_hash、資料指紋、期間、指標、結果檔路徑；append-only；統計「已試驗次數」供多重檢定 | 無法修改或刪除舊試驗；重跑同一試驗得到相同紀錄 |
| S4-W02 期間切分與鎖定 | 開發、驗證、鎖定保留期與前向期間定案（初版建議：開發 2003-06～2016-12、驗證 2017-01～2021-12、保留 2022-01～2026-09、前向 2026-10 起）；保留期每個候選只能評估一次並留存取紀錄；記錄 2025 年起資料曾被舊研究使用的已知限制 | 存取保留期需經程式關卡；紀錄可查 |
| S4-W03 統計檢定 | Deflated Sharpe Ratio、回測過度擬合機率（PBO／CSCV）、相對定期定額超額的 bootstrap 信賴區間；穩健性：成本加倍、晚一天執行、美股同規則對照 | 以已知案例驗證計算；報告格式固定 |
| S4-W04 AI 研究員 | LLM Provider adapter（見待確認）；讀研究日誌 → 提出假設與理由 → 產生設定檔（Schema 驗證）→ 回測 → 分析結果 → 下一個假設；只在夜間執行，設每日試驗數與 API 費用上限；禁止指名個股 | 研究日誌完整；超過預算自動停止；不合規設定檔被拒絕並記錄 |
| S4-W05 第一批研究 | 六個方向：薪資日投入時點、定期不定額（依回撤或均線調整金額）、核心部位趨勢／波動度控制、ETF 輪動（市值型、高股息、債券）、核心＋衛星（衛星最多 20%，用月營收或動能規則）、盤後零股限價與成交率取捨 | 研究報告列出每個方向的結果、淘汰原因與目前冠軍 |
| S4-W06 晉級流程 | 候選 → 驗證 → 保留期 → 前向模擬 → 晉級；使用者在研究頁核准才接入決策引擎 | 晉級紀錄含所有證據連結；未核准的策略不會出現在今日頁 |

晉級門檻初版（S4-W03 完成後以基準分布校準）：
- 相同現金流下，滾動 3 年與 5 年期間勝過定期定額的比例 ≥ 60%，中位數超額 > 0。
- 最大回撤不比定期定額深超過 5 個百分點。
- 成本加倍、晚一天執行後仍勝過定期定額的比例 ≥ 50%。
- 多重檢定調整後（DSR）仍顯著；PBO ≤ 0.2。
- 前向模擬至少 8 週且流程無異常；績效只作觀察，不作為單獨晉級依據。

依賴：S3。待確認：LLM Provider（Anthropic Claude 或既有 OpenAI 設定）與每月 API 預算上限。

## S5 決策核心、帳務與前向模擬

目標：每天輸出可執行的委託單或「不需操作」，記錄實際成交，並與定期定額對帳。

| 工作包 | 內容 | 驗收 |
|---|---|---|
| S5-W01 投資計畫 | 目標、每月投入金額、薪資日、允許標的、目標配置、再平衡區間、預備金、可承受回撤；版本化 | 計畫變更產生新版本；決策引用版本號 |
| S5-W02 決策引擎 | 資料快照 → 計畫與持倉 → 晉級策略版本 → 委託單（標的、股數、限價、有效期限、預估費用）；輸出類型：不需操作／按計畫投入／再平衡／風險處理／暫停新建議；識別碼鏈完整 | 同輸入同輸出；不超過可用現金；過期委託不可沿用；分數不顯示為機率 |
| S5-W03 成交回報與帳務 | 今日頁一鍵回報成交（股數、價格）；支援券商對帳單 CSV 匯入；實際帳戶帳務、股利入帳 | 未成交不計入持倉；手續費與稅計算與券商一致 |
| S5-W04 定期定額影子帳戶 | 用使用者真實現金流日期與金額模擬「同一天改買基準 ETF」；XIRR、回撤對照 | 任一日期可查兩帳戶差異 |
| S5-W05 前向模擬 | 研究候選策略以模擬帳戶逐日執行，保存當天真實產生的建議；每週摘要 | 8–12 週紀錄完整；可對帳 |
| S5-W06 退場舊決策程式 | `after_hours_ai.py`、`decision_support.py` 的有效規則轉為策略設定檔；固定權重組分移除 | 新舊結果差異有說明；舊檔不再被每日流程呼叫 |

依賴：S3；S4 晉級結果接入時需 S4-W06。
