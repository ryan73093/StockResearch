# 研究流程與機器資源

適用：啟動、停止、排隊研究流程；用 CPU、顯示卡、記憶體、磁碟。這台電腦同時跑其他專案與使用者自己的工作。決定原文在 `docs/decisions.md`。

## 啟動與停止

- 研究 CLI 在專案根目錄以 `$env:PYTHONPATH="src"` 從原始碼執行；避開 13:30–14:40（D-031）。
- 長時間程式（抓資料、大掃描、批次回測）一律用 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start-research.ps1 -Name <流程>` 在背景啟動：以 WMI 建立程序、脫離助理的工作階段，用 `conhost --headless` 執行、不開任何視窗；步驟、開始結束時間與結束碼寫在 `instance\research\logs\<流程>-<時間>-pipeline.log`；登錄到 `instance/research/jobs/`（網站「研究 › 執行中的程式」顯示名稱、進度、預計完成時間）（D-032、D-013）。
- 啟動後告訴使用者跑了哪些程式、在做什麼、大約何時跑完、進度與紀錄在哪裡看（D-013）。
- 被系統結束的步驟（關機、重開機、主控台關閉）標成「中斷」，服務下次啟動時自動重開；16:00 核對沒有中斷了沒恢復的流程（D-032）。
- 不用耗 token 的輪詢或反覆查看去等；用不耗 token 的背景等待，等待期間做下一個最佳化（D-032、D-011）。
- 停流程只用 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\stop-research.ps1 -Name <流程> -Reason <原因>`：只結束核對過的程序，紀錄標「stopped」與原因；不用 Stop-Process。換引擎或做法以後，還在用舊做法跑的流程當輪就停（D-033）。
- 16:00 核對桌面沒有本專案開出的視窗（`invariants.own_windows`：本專案程式的視窗，或標題帶專案路徑、.venv、研究腳本的主控台）（D-013）。

## 排隊

- 要跑的就馬上跑。只有三種情況可以排隊：13:30–14:40 盤後單時段、顯示卡記憶體被另一個程序佔用、要等前一步的資料；排隊用 `scripts/research-pipeline.ps1` 的 `Wait-While`，網站顯示「等待中」與原因（D-035）。
- 每個流程結尾的全部重算（統計、名單、驗證期、前向、看板）同時只跑一個；排隊中的流程共用排隊後才開始的那一次，不靠猜「資料有沒有變」跳過（`research/shared_steps.py`）；比較晚跑完的舊看板不蓋過新看板（D-025）。

## 資源

- 研究流程與每個研究步驟用最低優先權（Idle：`scripts/start-research.ps1` 建立時、`scripts/research-pipeline.ps1` 開頭設定，子程序繼承）。網站 web／api、worker（13:50 收盤表、盤後紀錄）與盤中的 `liveflow` 維持一般——被拖慢會記到錯的時間點。16:00 核對（`invariants.priority_check`）（D-025）。
- 開新的長時間研究前先看機器上有沒有別的重工作（編譯、其他專案），有就少開（D-025）。
- 能放顯示卡的計算（大規模搜尋、深度學習）用顯示卡版本，不在 CPU 上開；逐筆模擬的批次同時最多兩個程序（`Wait-ForSimulationSlot`）（D-036）。
- 記憶體（31 GB）：每個步驟開始前 `Wait-ForMemory`（深度學習訓練 24 GB 可用、加上櫃的 dl-2.2.x 40 GB、其他 16 GB；深度學習訓練中其他步驟先等）；重播大量帳戶或規則的程式不把每個規則的大陣列一直留在記憶體；16:00 核對過去 24 小時沒有用完（D-036）。
- 磁碟：每個步驟開始前等 C 槽可用 30 GB（`$DiskGB`），16:00 要 50 GB。
- 不自己拿其他硬碟、外部空間或雲端存資料；備份只用專案自己的位置，要用別的先問使用者（D-026）。

## 檢查

- 每一項需求檢查都拿「應該是什麼」比「實際是什麼」；日期從交易所日曆算（`invariants.due_session`），不從被檢查的資料自己算；新檢查先讓它在壞掉的狀況下不通過（測試）；16:00 沒過的項目當天處理（D-034）。
