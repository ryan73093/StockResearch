# 網頁介面

適用：改網站頁面（Flask + Jinja + HTML）。決定原文在 `docs/decisions.md`。

## 頁面結構

- 主導覽六項：今日、持倉、計畫、研究、議題、系統（D-004）。
- 每頁的區塊用分頁，不要長捲動；表格放得進畫面、表頭固定、每欄有說明。
- 研究總覽是唯一的策略總表；前向觀察只在每個策略自己的頁面（研究導覽沒有「前向觀察」分頁，舊網址導回總覽）。任何新頁面都先問：使用者是不是從總覽點策略進來的（D-021）。
- 研究頁以策略為中心（D-019）：每個策略一個固定編號（第一次登錄的試驗編號，重跑不變；`research/numbers.py`），每一頁的規則名稱前面都有 #編號，`/research/no/<編號>` 直接開；規則頁共用一個標頭（研究總覽 › 類別 › #編號、輸入編號開啟、回測表現／前向觀察兩個分頁）；前向帳戶每一筆交易都列買進價、賣出價與當天開盤／收盤；研究頁先給背景每分鐘算好的結果，不在開頁時重算。16:00 實際開研究總覽、規則頁、前向頁，量時間（超過 5 秒算沒過），核對編號與買進價／賣出價欄位。

## 研究總覽

- 滿版、以圖為主的儀表板：比較與趨勢一律畫成圖（線圖、長條圖，`research/charts.py`：桌面與手機各畫一份、滑鼠移上去看數字、線尾標名字）；表格只放在浮動視窗裡的清單；任何數字都寫出單位與意思（每年報酬 %、萬元、幾倍），不放沒說明的數字串；說明收進可展開的「怎麼算的」（D-018）。
- 每張「最後有多少錢」的分佈圖（回測兩個賽道、前向帳戶全部賣掉）在柱子下面每一類一列，畫出這一類的分佈、中位數與中間一半，點一列開這一類自己的分佈圖（`research/distribution.py`）；16:00 核對每一類都有一列（D-018）。
- 排名、「最好」與成績照 D-020：用實際結果，帳面獲利另列、標明不算。

## 議題追蹤

- 議題只是提醒，不改策略、不下單；新議題照同一套（追蹤什麼、為什麼、警示線、告警線、來源）加進 `research/issues.py`（D-004）。
- 每個議題一個專案：`/issues` 是專案清單與候選議題，`/issues/<專案>` 各自一頁（要回答的問題、燈號、判讀、圖、門檻、燈號變化）；一個大議題拆成它真正的幾個問題，各自一個專案；專案選擇是 app 式的格子與切換列（D-004、D-019）。
- 每個專案都有手寫的判讀（`research/issue_notes.py`），燈號變了 7 天內重寫，16:00 核對；候選議題寫出為什麼值得追、追什麼、門檻與資料來源，給使用者挑（D-004）。

## 驗收

- UI 變更實際開頁看桌面與 375 px 寬，像使用者一樣逐頁讀（單位、相同的列、過期的文字），看總覽的「正確性核對」。
- 頁面讀的資料多加欄位時，樣板要在沒有那個欄位時也能顯示（背景程序預先算好的資料、別的程序的快取可能是上一版寫的）；部署後打一次 `/research` 確認是 200（11/12 部署後 500 一分鐘）。
