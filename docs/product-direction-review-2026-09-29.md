## 使用者產品

建議第一版以台灣、台幣、人工確認操作為產品假設；是否開放海外資產須由使用者可用帳戶與需求決定。

首次設定：資金用途、預計使用時間、每月可投入金額、現有持倉與現金、資金需求、可承受虧損、允許市場與操作頻率。不能只問「保守／積極」，也不能在缺少這些資料時給個人買賣金額。

首頁只保留：

- 今日行動：不需操作／按計畫投入／再平衡／需要處理的風險／暫停產生新建議。
- 行動內容：標的、數量或金額、交易時間條件、成本估計、有效期限。
- 決策依據：資料日期、觸發規則、政策版本、與目前持倉的差異。
- 風險：集中度、現金缺口、情境下的可能損失；風險門檻不是損失保證。
- 實際結果：成交後持倉、費用、資產變化、與同期間同現金流基準的差異。

每日更新狀態；按週或月檢視策略；只有達預設條件才交易。資料失效時停止新建議並解釋原因，不自動把原有持倉解讀成必須賣出。

## 策略與 AI

| 層次 | 第一版用途 | 加入條件 |
|---|---|---|
| 核心配置 | 分散、低成本、長期持有與規則式投入 | 符合期限、資金需求與風險承受能力 |
| 趨勢／動能 | 可選的低頻主動研究 | 獨立樣本扣成本有效、可執行、回撤可接受 |
| ML | 挑戰簡單基準的排序或風險模型 | 同資料、同成本、同執行假設比較後仍有增益 |
| LLM | 解釋已計算的決策、摘要可追溯公告、回答持倉問題 | 每個關鍵事實有來源；數字由計算服務提供 |
| 強化學習 | 暫留研究用途 | 前述流程可靠後再評估是否值得投入 |

不把既有 80/20 當成適用每人的最佳比例。核心策略先可獨立工作，主動配置從零開始；沒有優勢時繼續為零。趨勢研究支持值得驗證的假設，不足以證明某個台股選股系統有效。

## 執行順序與驗收

### 1. 每日流程可信

修正官方交易日曆與臨時休市，核對兩檔過期標的原因，整理資料來源優先順序、重試上限、資料版本與更新狀態。針對目前錯誤加入交易日情境測試。資料庫評估先看查詢計畫、索引、增長來源、WAL 和還原演練，再決定是否遷移 PostgreSQL 或分離歷史分析資料。

驗收：9/25、9/28 休市不誤報；真正缺資料仍阻擋依赖該資料的建議；每次失敗可定位與重試；備份可還原。

### 2. 建立一致的決策契約

串接資料快照 → 使用者政策與持倉 → 合格策略版本 → 成本與部位計算 → 建議 → 成交回報 → 帳務。每一步保存識別碼。先做不依賴 ML 的基準組合及「不需操作」。

驗收：同輸入可重現；建議不超過可用現金；尚未成交不計入持倉；過期建議不能沿用；研究分數不顯示成機率。

### 3. 驗證主動策略

比較少量事先定義的政策：基準持有與固定投入、低頻再平衡、簡單趨勢、最多一個 ML 挑戰者。統一總報酬、股利、分割、交易時點、稅費、滑價、無法成交處理及歷史股票池。採時間序列外推評估，記錄所有試驗，保留真正未參與選模的最終期間。

驗收：同風險與現金流下比較扣成本報酬、回撤、換手、最差期間和使用者操作次數，並揭露估計不確定性。若沒有穩健增益，主動策略不上線；不能因工程已完成而降低投資門檻。

### 4. 前向模擬與使用驗證

逐日保存當時真實產生的建議，核對模擬成交、帳務與基準。先以 8–12 週觀察操作流程與可靠性；這段時間不足以證明長期超額報酬。績效驗證需更長期間與不同市場狀態。

驗收：一般日使用者可在三分鐘內理解是否需要操作；帳務可對帳；警示只在有影響時出現；不為了每天有新內容而產生交易。
