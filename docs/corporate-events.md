# 法說會與重大事件（v3.8）

## 設計理念

法說會「何時公告」與「何時舉行」是兩個不同時間。公司可能在活動前數日公告，因此事件資料允許 `available_time < event_time`；但永遠要求 `available_time <= ingested_at`。回測只從公告可用時間開始讀取，不能在公司公告前知道未來法說會。

## 官方來源

| 市場／用途 | 官方來源 | 更新與限制 |
|---|---|---|
| 上市公司每日重大訊息 | TWSE OpenAPI `t187ap04_L` | 目前每日資料；平台從實際下載日起累積 |
| 上櫃公司每日重大訊息 | TPEx OpenAPI `mopsfin_t187ap04_O` | 目前每日資料；平台從實際下載日起累積 |
| 單一公司最新法說會明細 | MOPS 相容查詢 `t100sb07_1` | 補充最新簡報、公司網站與影音；不是完整歷史 API |

平台只保留主旨或說明包含「法人說明會／法說會／法說」的公告。每筆保存公司、掛牌市場、公司發言時間、法說會時間、地點、摘要、條款、官方簡報、影音、來源 URI、內容 SHA-256 與修訂鍵。

## 使用方式

1. 開啟 `/corporate-events`。
2. 輸入 `ALL` 後按「更新官方法說會」，收集當日上市與上櫃公告。
3. 輸入 `2330` 等單一代號，再次更新，補充該公司最新 MOPS 簡報與影音。
4. 以「全部／尚未舉行／已經舉行」篩選。
5. 核對「公告可用時間」與「法說會時間」，兩者均以台北時間顯示。

FastAPI：

- `GET /api/v1/corporate-events?symbol=2330&scope=all`
- `POST /api/v1/pipelines/corporate-events?symbol=ALL`

每日台股排程會自動執行 `ALL` 更新。單一公司詳細查詢仍由使用者按需執行，避免不必要地對 MOPS 發送大量請求。

## 可帶來的研究效益

- 建立法說會公告後及舉行後的 1／5／20 日事件研究。
- 比較管理階層展望、財報關鍵字與模型預測是否一致。
- 結合法人買賣、成交量、波動與市場狀態，檢驗事件在哪些環境有效。
- 將官方簡報與摘要加入 RAG 知識庫，讓回答具備可追溯來源。

## 限制

- OpenAPI 是目前每日資料，不提供完整歷史快照；啟用前的公告不能宣稱具有 Point-in-time 歷史。
- MOPS 相容查詢目前用於單一公司最新明細，不批次爬取全市場歷史。
- 本模組保存事件證據，尚未完成事件超額報酬、文字情緒及管理層語意模型。
- 法說會不等於利多；任何訊號仍需成本後、樣本外與相對大盤驗證。
