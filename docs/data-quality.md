# Point-in-time 資料品質與缺漏監控 v3.4

## 設計目的

資料有問題時，模型輸出不具投資意義。本模組把資料品質變成每日研究的硬性前置條件，而不是只在網頁顯示警告。

## 四個時間概念

1. 事件時間：價格、財報或總經數值實際所屬時間。
2. 公開時間：資料來源正式發布、研究可以開始使用的時間。
3. 匯入時間：平台取得並保存該資料版本的時間。
4. 計算時間：特徵或研究結果產生的時間。

行情與特徵必須遵守事件時間不晚於公開時間，公開時間不晚於匯入或計算時間。行情 `as_of` 查詢會先排除當時尚未公開版本，再選取同一交易日當時最新可見修訂版。

## 品質政策 v1

- 啟用標的日線覆蓋率至少 90%。
- 整體市場行情不得落後檢查時間超過 5 個工作日。
- 個別標的落後市場超過 1 個交易日列警告，超過 3 個交易日列嚴重問題。
- 最近最多 63 個共同交易日，缺漏率達 10% 列警告，達 25% 列嚴重問題。
- 價格必須大於 0 元，高低價需包住開收盤價，成交量不得小於 0 股。
- 完整階段每檔至少具備 8 項最新技術特徵，市場特徵覆蓋率至少 80%。
- 台股籌碼／估值及必要總經序列缺少先列警告，避免把月、季資料誤當成每日缺漏。

## 每日流程

1. 更新行情、台股研究資料與總經資料。
2. 執行原始資料品質閘門；嚴重問題立即停止。
3. 建立 Feature／Label Store。
4. 執行完整資料品質閘門；特徵不足立即停止。
5. 只有通過後才執行模型、因子、回測、策略整合、投資組合與每日決策。

## 使用方式

開啟 `http://127.0.0.1:5000/data-quality`，分別按「檢查台股完整資料」或「檢查美股完整資料」。頁面會顯示研究是否允許、覆蓋率、缺漏數、每項規則與可處理問題。

FastAPI：

- `GET /api/v1/data-quality`
- `POST /api/v1/data-quality/TW?stage=full`
- `POST /api/v1/data-quality/US?stage=raw`

所有比例顯示 `%`，數量顯示個、筆、項、序列或交易日；資料指紋是識別碼，沒有金融單位。
